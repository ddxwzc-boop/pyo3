Make failed `extract` for the `int` and `float` families lazy: when the input type has no `__index__` (resp. `__float__`) slot and is not an `int` (resp. `float`), extraction now short-circuits to a lazily-constructed `TypeError` instead of entering `PyLong_AsLong` / `PyFloat_AsDouble`, which constructs a real exception inside the interpreter that is immediately fetched again and typically dropped without ever being observed. The error type and message text match CPython's own (built from `tp_name`), stored inline in the lazy `PyErr` state. `extract_int_extract_fail` drops from ~116ns to ~39ns and `extract_float_extract_fail` from ~96ns to ~41ns on the benchmark suite. Note that consumers which format the error message (e.g. enum `FromPyObject` derive, which decorates variant errors with their messages) will materialize the error as before.
